# record-demo — видео-демо фичи из ветки

Результат — `~/Downloads/skill-atlas-<branch>-demo.mp4` (1280×800, H.264, с подписями
шагов) и лист кадров рядом для проверки. Видео **не коммитится**: пользователь
перетаскивает его в PR (API для загрузки видео в PR у GitHub нет).

Все пути ниже — относительно этой директории (`.claude/skills/record-demo/`).

## Шаги

1. **Понять, что показывать.** Ветка — из аргумента (по умолчанию текущая).
   Прочитай `git diff main...<branch>` и изменения README (README — спека): демо
   показывает поведение из спеки глазами пользователя, включая заметные корнер-кейсы
   (ошибки, валидацию, пустые состояния), а не только happy path.

2. **Поднять продукт из ветки:**
   ```bash
   ./serve-branch.sh <branch>
   ```
   Скрипт находит worktree ветки (или создаёт `../demo-<branch>`), копирует туда
   локальный `gradle.properties`, собирает `shadowJar`, запускает `serve` на свободном
   порту и печатает `URL=… PID=… LOG=… WORKTREE=…`. Токен GitHub: `GITHUB_TOKEN`, иначе
   `gh auth token` (аккаунт — `DEMO_GH_USER`, если задан). Без токена быстро упрёшься
   в rate limit — предупреди пользователя.

3. **Написать сценарий** в `${TMPDIR:-/tmp}/skill-atlas-demo/<branch>.mjs` — ES-модуль с
   `export default async ({ page, url, caption, pause, type }) => { … }`:
   - `caption(text)` — плашка с подписью шага (английский, коротко: что сейчас видно);
   - `type(locator, text)` — печать с видимой скоростью; `pause(ms)` — дать зрителю прочитать;
   - ждать результатов по селекторам (`page.waitForSelector`), не фиксированными паузами;
   - после каждого шага пауза 1.5–3 с; целевая длина — 30–90 с;
   - селекторы брать из `src/main/resources/web/index.html` ветки;
   - публичные репо для скана: `anthropics/skills`, `anthropics/claude-code`;
     для ошибок — несуществующий `nope/does-not-exist`.

   Образец — `examples/multi-repo.mjs`.

4. **Записать:**
   ```bash
   ./record.sh "${TMPDIR:-/tmp}/skill-atlas-demo/<branch>.mjs" "<URL>" ~/Downloads/skill-atlas-<branch>-demo.mp4
   ```
   Первый запуск ставит Playwright в `node_modules/` этой директории и его ffmpeg
   (браузер не качается — используется установленный Chrome). Печатает `VIDEO=…` и
   `FRAMES=…`.

5. **Проверить.** Открой `FRAMES` (Read) — 8 кадров по всей длине. Каждый шаг
   сценария должен быть виден, без пустых экранов, зависших спиннеров и сообщений
   об ошибке, которых не было в плане. Если что-то не так — поправь сценарий и
   перезапиши (шаг 4).

6. **Прибрать:** `kill <PID>`. Worktree `../demo-<branch>`, если скрипт его создал,
   оставь — скажи пользователю, что его можно убрать `git worktree remove`.

7. **Отчитаться:** путь к видео, длительность, список показанных шагов. Предложи
   вставить его в раздел «Видео-демо» PR.

## Ограничения

- Пишется только web UI (`serve`). Если фича чисто CLI — не записывай терминал
  «вслепую»: предложи пользователю вставить в PR вывод `scan` в нужных форматах
  текстом или записать терминал самому (`⌘⇧5`).
- Нужны `node`, `ffmpeg` (`brew install ffmpeg`) и Google Chrome; другой канал браузера —
  через `DEMO_BROWSER_CHANNEL` (например, `msedge`).
